# Application management preview

This is an isolated visual prototype for review before product implementation. Application source, routes, business rules and theme files are unchanged.

## Existing evidence

- Target: `src/features/freelancer/pages/MyApplicationsPage.tsx` at `/freelancer/applications`.
- Shared shell: `FreelancerHeader`, `FreelancerNav`, `freelancerTheme` and `freelancer-home.css`.
- Existing identity: orange `#f4490b`, dark ink `#20201f`, background `#f7f8f6`, freelancer divider `#a8b0a2`, Archivo headings, Be Vietnam Pro / Space Grotesk text, 13px surfaces and pill controls.
- Existing discovery screen uses a list and right detail column, strong selected borders and an orange offset shadow.
- Current application screen uses an isolated 1100px container, large summary cards and internal screen/requirement IDs in customer copy.

## Proposed layout

Preserve the header, navigation labels, route, brand and existing UI library. Use the available page width, one compact overview strip, status tabs, search and a list/detail arrangement matching project discovery. Group application status and permitted actions, with progress and the submitted proposal in the detail rail. Remove internal requirement IDs from visible copy.

Design dials: DESIGN_VARIANCE 4, MOTION_INTENSITY 2, VISUAL_DENSITY 5. Static light-theme review matching the current project. No new design system or dependencies.

## Requirements

- FL-009, FR-027: application tracking with project, capacity, source, submission date and state.
- FL-012, FR-028: confirmation before withdrawal, only while pending; preserve history.
- FR-031 and BR-013: business review gates project chat; accepting an invitation alone does not unlock chat.
- FLOW-06, FLOW-08, FLOW-12: application, review and withdrawal flows.
- NFR-01 and NFR-02: responsive layout and accessible controls.

The UI scope and SRS files under `docs/` are the source for these mappings. Some old inline BR references in the current component and AGENTS.md differ from the final SRS; this preview uses the final screen specifications and does not change business logic.

## Preview scope

The four applications, companies, dates and current agreement are explicitly illustrative. The preview is isolated from normal routes and uses a separate automated browser context. Search, tabs, the empty state, detail selection and withdrawal confirmation can be reviewed. Navigation to agreement/project/chat pages is represented by labeled prototype feedback. No backend action, real withdrawal or production agreement is performed.

Desktop and mobile PNGs are generated by `capture-applications-prototype.mjs`. Verification results are saved in `applications-prototype-checks.json`. Product typecheck/lint/build are outside this visual-only preview; no product implementation is claimed.
